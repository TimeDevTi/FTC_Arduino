# FTC Mecanum Teleop — UNO R4 Minima + FlySky iBUS (ไม่มี ESP32)

บอร์ด **Arduino UNO R4 Minima ตัวเดียว** รับสัญญาณจากรีซีฟเวอร์ FlySky ทาง **iBUS เส้นเดียว (D0)**
แล้วผสมค่า mecanum และสั่งมอเตอร์ทั้ง 4 ตัวเองผ่านพิน **D3, D4, D5, D6, D7, D9, D10, D11**
ส่วนพอร์ต USB ทำหน้าที่ **ส่ง telemetry อย่างเดียว** ให้แล็ปท็อปแสดงผลว่าล้อถูกสั่งค่าอะไรจริง ๆ

## การต่อสายมอเตอร์ (8 พินตามที่กำหนด)

| ล้อ | ไดรเวอร์ | พินบน UNO R4 Minima |
|---|---|---|
| FL (หน้าซ้าย) | MDD3A M1 | D3, D5 |
| FR (หน้าขวา) | MDD3A M2 | D6, D9 |
| RL (หลังซ้าย) | MD10C R3 | D10 (PWM), D4 (DIR) |
| RR (หลังขวา) | MD10C R3 | D11 (PWM), D7 (DIR) |

## การต่อรีซีฟเวอร์ FlySky (3 สาย ไม่ใช่ 3 ช่องสัญญาณ)

ต่อจากพอร์ต **i-BUS / servo** ของรีซีฟเวอร์เข้าบอร์ดใช้เพียง 1 เส้นสัญญาณ:

| สาย | ต่อเข้า | หมายเหตุ |
|---|---|---|
| Signal (ขาว/เหลือง) | **D0** (Serial1 RX) | 115200 baud, 8N1 — ส่งทุกช่องมาในแพ็กเก็ตเดียว |
| 5V (แดง) | ราง 5V เดียวกับที่ไดรเวอร์มอเตอร์ใช้ | พ่วงจากจุดเดิมได้ ไม่ต้องหาแหล่งใหม่ |
| GND (ดำ) | GND | ต้องร่วม GND กับแบตเตอรี่มอเตอร์ |

- ช่องที่โค้ดอ่าน: **CH1 = strafe, CH2 = forward, CH4 = turn** (แก้ได้ที่ `IBUS_CH_*` ใน `include/robot/Config.h`)
- **พิน 5V ถูกใช้กับไดรเวอร์มอเตอร์อยู่แล้ว ไม่เป็นปัญหา**: ต่อพ่วงรีซีฟเวอร์เข้าราง 5V เดิม (แกะสายหรือใช้ Y-cable/servo splitter) เพราะรีซีฟเวอร์กินไฟหลักสิบ mA เท่านั้น
- ถ้าไม่อยากพ่วงรางเดียวกับไดรเวอร์ ให้ใช้ BEC 5V แยกจากแบตเตอรี่มอเตอร์ แล้วต่อเฉพาะ GND ร่วมกัน
- **ห้ามเลี้ยงรีซีฟเวอร์จากพิน 3.3V** — รุ่น iBUS ส่วนใหญ่ต้องการ 4.0–6.5V (ต่ำกว่านั้นอาจไม่ติด/หลุดง่าย)
- ต้องเป็นรีซีฟเวอร์ที่มีพอร์ต iBUS เช่น **FS-iA6B, FS-iA10B, FS-X6B** — รุ่น FS-iA6 ธรรมดา (มีแต่ PWM) ใช้ไม่ได้
- `D1` (TX ของ Serial1) ไม่ต้องต่อ ส่วน `D2, D8, D12, D13, A0–A5` ว่าง
- ถ้าทิศทางสติ๊กกลับด้าน ให้กลับด้านที่ช่องนั้นในเมนูรีโมต (FlySky FS-i6: Functions → Reverse) ไม่ต้องแก้โค้ด
- ถ้าอัปโหลดแล้วเจอปัญหา ให้ถอดสายสัญญาณ iBUS ออกตอนอัปโหลด (บอร์ดรีเซ็ตระหว่าง DFU)

## พฤติกรรมการทำงาน / ความปลอดภัยในโค้ด

- **ต้อง arm ก่อน**: หลังบูตหรือหลังสัญญาณหลุด สติ๊กทั้งสามต้องอยู่กลาง (±5%) ต่อเนื่อง 300 ms มอเตอร์จึงจะเริ่มหมุน (กันรีโมตค้างคันเร่งตอนเปิดเครื่อง)
- **failsafe**: ถ้าไม่มีเฟรม iBUS ที่ถูกต้องเกิน 100 ms (รีซีฟเวอร์ไม่มีไฟ / สายหลุด / checksum ผิด / ค่าเป็น 0) มอเตอร์หยุดทันทีและต้อง arm ใหม่
- ค่าช่อง 1000–2000 µs แปลงเป็น -100..100% โดยมี deadband ±50 µs รอบกลาง (1500 ±50 อ่านเป็น 0%) และถึง ±100% ที่ 1000/2000 µs — ที่ 1050/1950 µs ได้ประมาณ ±88%
- ยังเป็น open-loop (ไม่มี encoder/PID) และไม่ใช่ emergency stop ที่ผ่านการรับรอง — ควรมีสวิตช์ตัดแบตเตอรี่ที่เอื้อมถึงเสมอ

## ดู feedback ว่าล้อถูกสั่งจริง (หน้าเว็บ)

บอร์ดส่งบรรทัด CSV ออกทาง USB 20 Hz:

```text
T,<ms>,<ch1>,<ch2>,<ch4>,<strafe%>,<forward%>,<turn%>,<FL>,<FR>,<RL>,<RR>,<link>,<armed>
```

- หน้าเว็บอ่านค่านี้ตรง ๆ ด้วย **Web Serial API**: เปิด `tools/telemetry.html` ใน **Chrome หรือ Edge**
  แล้วกด “เชื่อมต่อ USB” เลือกพอร์ตของบอร์ด (115200) จะเห็นแถบค่าของ CH1/CH2/CH4,
  ค่า PWM ของล้อทั้ง 4 ตัวที่สั่งจริง, สถานะ LINK (มีเฟรม iBUS สด) และ ARMED
- ถ้าเปิดเป็นไฟล์แล้วเบราว์เซอร์ไม่ให้ใช้ Web Serial ให้เสิร์ฟผ่าน localhost:
  ```sh
  python3 -m http.server
  # เปิด http://localhost:8000/tools/telemetry.html
  ```
- ดูดิบ ๆ ได้ที่ `pio monitor` (115200 baud) หรือ Serial Monitor ของ Arduino IDE

## คอมไพล์และอัปโหลด

```sh
pio run -e r4_minima            # compile
pio run -e r4_minima -t upload  # upload (กด double-tap RESET ให้เข้า DFU)
pio monitor                     # 115200 baud
python3 tools/test_native.py    # เทสต์ที่ไม่ต้องใช้บอร์ด (รวม parser iBUS)
```

## การทดสอบครั้งแรก

1. ยก wheels ขึ้นให้พ้นพื้น และยังไม่ต่อแบตเตอรี่มอเตอร์
2. อัปโหลด เปิด `pio monitor` ดูว่ามีบรรทัด `T,...` ไหลออกมา และ `link` เป็น 1 (แปลว่าได้เฟรม iBUS แล้ว)
3. เปิด `tools/telemetry.html` แล้วขยับสติ๊ก ดูว่าตัวเลขเปลี่ยนตาม — นี่คือค่าที่สั่งไปที่ไดรเวอร์จริง
4. ต่อแบตเตอรี่มอเตอร์ ใช้ความเร็วต่ำ ตรวจทีละล้อว่าทิศตรงกับที่สั่ง (ถ้ากลับด้านให้แก้ `inverted` ใน `include/robot/Config.h`)
